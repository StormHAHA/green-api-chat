# GREEN-API Chat

Веб-интерфейс для отправки и получения текстовых сообщений в Telegram через сервис [GREEN-API](https://green-api.com/telegram). Интерфейс сделан по образцу веб-версии [MAX](https://web.max.ru/). ТЗ допускает Telegram вместо MAX, поэтому используется Telegram-инстанс GREEN-API.

## Возможности

- Вход по учётным данным инстанса GREEN-API (`idInstance`, `apiTokenInstance`). Адрес API подставляется автоматически по `idInstance`
- Создание чата по номеру телефона получателя
- Отправка текстовых сообщений методом [SendMessage](https://green-api.com/telegram/docs/api/sending/SendMessage/)
- Получение сообщений по технологии [HTTP API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/): `ReceiveNotification` → обработка → `DeleteNotification`
- Входящие от новых собеседников автоматически появляются в списке чатов
- Статусы отправки, повтор неотправленного сообщения, счётчик непрочитанных
- История переписки сохраняется в `localStorage` отдельно для каждого инстанса (последние 500 сообщений в каждом чате)
- Адаптивная вёрстка и тёмная тема

## Быстрый старт

Требуется Node.js 22.12 или новее.

```bash
npm install
npm run dev
```

Приложение будет доступно по адресу http://localhost:5173.

## Настройка инстанса

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com), создайте инстанс и авторизуйте в нём аккаунт Telegram.
2. В настройках инстанса включите **«Получать уведомления о входящих сообщениях и файлах»**.
3. Поле **URL для отправки уведомлений** (`webhookUrl`) должно быть пустым, иначе уведомления не будут доступны через HTTP API.
4. По желанию включите **«Получать уведомления о сообщениях, отправленных с телефона»**: такие сообщения тоже появятся в чате.

## Сценарий проверки

1. Откройте приложение и введите `idInstance` и `apiTokenInstance`.
2. Нажмите «Новый чат» и введите номер телефона получателя.
3. Напишите сообщение и отправьте его (Enter - отправить, Shift+Enter - перенос строки).
4. Ответьте на сообщение в Telegram: ответ появится в чате через несколько секунд.

## Особенности реализации

- **Идентификатор собеседника.** Во входящих уведомлениях Telegram собеседник определяется по внутреннему `chatId`, а не по номеру телефона. Поэтому при создании чата номер сначала проверяется методом [CheckAccount](https://green-api.com/telegram/docs/api/service/CheckAccount/): так ответы попадут в нужный чат. Если проверка временно недоступна (например, из-за лимитов), сообщение отправляется на `номер@c.us`, а чат сопоставляется с входящими по номеру телефона отправителя.
- **Получение уведомлений.** Используется long polling с `receiveTimeout=20`. У каждого запроса есть таймаут, поэтому зависшее соединение не остановит получение. При ошибках задержка перед повтором растёт экспоненциально до 30 секунд, а статус соединения виден в шапке списка чатов. Повторно доставленные уведомления отбрасываются по `idMessage`.
- **Одна активная вкладка.** Очередь уведомлений у инстанса одна, и при чтении из нескольких вкладок сообщения разошлись бы между ними. Поэтому получает сообщения только последняя открытая вкладка, остальные предлагают «Использовать здесь» (через `BroadcastChannel`).
- **Только текст.** Обрабатываются сообщения типов `textMessage` и `extendedTextMessage`. Остальные уведомления удаляются из очереди без отображения.

## Ограничения и компромиссы

**Хранение данных**

- История хранится только в `localStorage` этого браузера. На другом устройстве или после очистки данных сайта её не будет.
- Сообщения, полученные до первого входа, не подгружаются. Для этого нужен метод `GetChatHistory`, а по ТЗ получение сделано через уведомления.
- В каждом чате хранятся последние 500 сообщений, чтобы не упереться в лимит `localStorage` (около 5 МБ).
- История перезаписывается целиком при каждом изменении. На объёмах тестового задания это незаметно, для большой переписки лучше IndexedDB.
- Токен и переписка лежат в `localStorage` в открытом виде. Кнопка выхода удаляет токен, история остаётся. Для реального продукта токен стоит хранить на бэкенде.

**Получение сообщений**

- Уведомления хранятся в очереди GREEN-API 24 часа. Если приложение не открывали дольше, часть сообщений пропадёт.
- Приложение удаляет из очереди все уведомления, включая нетекстовые. Если инстанс использует ещё какая-то интеграция, она их не получит.
- HTTP API не работает при заполненном `webhookUrl`, это ограничение GREEN-API.
- Сообщения получает только одна вкладка.
- Сообщения, отправленные с телефона, появятся в чате, только если в настройках инстанса включены уведомления о них.

**Прочее**

- Создать чат можно только с номером, у которого есть Telegram и который не скрыт настройками приватности.
- Частые проверки номеров через `CheckAccount` Telegram может временно ограничить.
- Время своих сообщений берётся из часов компьютера, входящих - с сервера. Если часы сильно отстают, порядок сообщений может сбиться.
- Все сообщения чата рендерятся сразу, без виртуализации и подгрузки по частям.
